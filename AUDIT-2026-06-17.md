# warren-sdk-rs: Executive Audit Report

## 1. Overall Verdict

This SDK is **production-grade**. The cryptographic core (identity derivation, HPKE multihop session, TLS raw-public-key pinning, NAT-PMP/handshake/control codecs) is a faithful, byte-for-byte clean-room port of warren-core, pinned by shared golden vectors and exhaustively tested. The defensive posture is strong: deny_unknown_fields on every wire struct, post-signature anti-freeze/anti-rollback enforcement on authenticated fields, write-once TOFU pinning, consistent no-log discipline (no secret in any Display, verified by tests), zeroized secrets, and a clean panic-free FFI boundary that recovers from poisoned locks. `unsafe_code = forbid` holds workspace-wide except the two genuinely-required, well-annotated exceptions (FFI/uniffi and the experimental TUN backend). The findings below are hardening, polish, and feature-completeness gaps rather than correctness defects in the live (proxy + multihop) datapath. The biggest real risks cluster in two non-default/experimental areas: the experimental TUN datapath (firewall-state clobbering, v6 gateway mismatch) and FFI feature exposure gaps (anti-censorship hosts unreachable from foreign bindings).

## 3. Per-Dimension Health

- **Security:** Strong. Crypto core sound and wire-faithful; no-log + zeroization consistent. Gaps: voucher_secret Debug leak, dns_disabled downgrade defense missing, per-packet key not zeroized in warren-multihop, a few `#[derive(Debug)]` on pubkey/IP-bearing value types.
- **Performance:** Good on the QUIC plane (zero-copy recv, no lock-across-await). Hot-path allocations are the theme: double-copy seal, 1-byte-per-syscall HTTP CONNECT head, Vec-vs-Bytes egress copies; all medium/low.
- **Idiomatic:** Exemplary across all 12 crates. No unwrap outside tests, correct borrowing/builders/`#[non_exhaustive]`/async patterns. Only nits: `TransportError(String)` always-constant payload; swappable adjacent `[u8;32]` keys.
- **Tests:** Strong vector-driven TDD. Narrow gaps: reqwest_transport classification untested, several documented `# Errors` variants (`Framework`, `EmptyDaitaPool`, `TunnelError::Frame`, multihop `Hpke`) and pure pool/facade fns lack a direct test, TLS verifier branches (see High).
- **Docs:** Mostly complete (missing_docs clean, no em-dashes). Real defects: 5 broken intra-doc links, CHANGELOG self-contradicts on the removed Dart binding, ARCHITECTURE.md omits 3 crates and DAITA, dangling README reference.
- **Quality/Redundancy/Org:** Clean room intact (no warren-core dep, no cycles, no `todo!`/dead allows). Redundancy: 3 FFI constructors subsumed by `with_options`, dead `ConnectMode`/`mode::TunConfig`, duplicated multihop-exit test bodies, unused `TunConfig.dns`.
- **Feature-completeness:** Live datapath complete. Gaps are FFI knobs (`api_alternative_hosts`, `request_ipv6`, `auto_local_ip`), supervised-handle missing forward_port/metrics, failover onto a dns_disabled exit, orphaned/unreachable Windows Wintun path, unbuilt WFP killswitch.
- **Wire-compat:** Excellent, byte-for-byte verified for all frozen formats. One process gap: the multihop directory vector lives in a crate-local fixture, not the shared `vectors/` dir (CLAUDE.md rule 3).

## 4. Top 10 Prioritized Action Items

1. **Redact `RegisterAccountRequest::voucher_secret`** (drop Debug derive, hand-impl + test). Latent bearer-credential leak; violates project rule.
2. **Restore the `dns_disabled` downgrade defense** in multihop directory verification (track Unattested for v1-only; force `dns_disabled=false`).
3. **Add direct unit tests for the TLS RPK verifier / SPKI parse** rejection branches (primary MITM defense currently only covered end-to-end).
4. **Fix the experimental macOS killswitch teardown** to be state-preserving (anchor + snapshot), and fail-closed/family-match on v6 exits.
5. **Expose `api_alternative_hosts` (and `request_ipv6`, `auto_local_ip`) in `FfiClientOptions`** so foreign bindings get censorship circumvention and dual-stack.
6. **Zeroize the per-packet symmetric key in warren-multihop** (`Zeroizing<[u8;32]>` in `seal`/`open_response`) to match core's secret hygiene.
7. **Collapse the double-copy multihop seal** into a single in-place buffer (`seal_into`/`encode_into`); also buffer the HTTP CONNECT head read.
8. **Close the documented-error/pure-function test gaps** (`Framework`, `EmptyDaitaPool`, `TunnelError::Frame`, multihop `Hpke`, `DaitaPool::pick*`, FFI daita-only branch, reqwest_transport classification).
9. **Fix docs:** repair the 5 broken intra-doc links (+ add `-D rustdoc::broken_intra_doc_links` to CI), reconcile the CHANGELOG Dart contradiction, add the 3 missing crates + DAITA to ARCHITECTURE.md.
10. **Promote `multihop_directory.json` to the shared `vectors/` dir**, and decide the orphaned-code questions (Windows Wintun path, dead `ConnectMode`/`mode::TunConfig`, WFP killswitch doc claim).

## 5. AUDIT.md "FIXED" Claims Contradicted by Current Code

- **Anti-censorship fallback "FIXED" (AUDIT.md lines 88, 111):** The claim holds for the **SDK/warren-api layer** (primary / alternatives / no-SNI sequence is implemented and tested). It is **contradicted at the FFI boundary**: `api_alternative_hosts` is unreachable from `FfiClientOptions`, so no foreign binding can use the alternative-host path. Not a refuted SDK fix, but the feature is not actually shipped to embedders.
- **"HTTP head BufReader" listed as still-open in AUDIT's third pass:** confirmed **still unfixed** (`read_connect_target` reads one byte per syscall at proxy.rs:519-531). This is consistent with AUDIT (it was flagged open), recorded so it is not mistaken for resolved.
- **"All public items documented" claim masked broken doc-links:** item-level docs are complete (`-D missing_docs` clean), but 5 intra-doc links render as literal text rather than navigable links, an omission the "documented" claim did not surface.

All other "FIXED" security claims spot-checked (deny_unknown_fields, post-signature validity cap, anti-rollback generation floor, TOFU write-once persistence, no-log Display, zero-copy datagram recv, QUIC TransportConfig constants) were **confirmed present in current code**.

### [HIGH] Per-packet multihop send does two heap allocations and two full-packet copies on the hottest datapath

- **Area:** warren-multihop / warren-wire  
- **Dimension:** performance  
- **Location:** `crates/warren-multihop/src/lib.rs:275 and crates/warren-wire/src/multihop.rs:95`  
- **Evidence:** In ClientSession::seal: `let mut buf = payload.to_vec();` (alloc+copy #1, sized exactly to the payload with no headroom), then the frame is encoded with `let bytes = postcard::to_stdvec(self)?;` in WarrenMultihopFrame::encode (alloc+copy #2, which copies the entire ciphertext again into the postcard buffer). The frame layout is frozen and MULTIHOP_FRAME_MAX_OVERHEAD (83) is a fixed prefix-only overhead. Collapse the two allocations: have seal allocate one buffer with capacity `MULTIHOP_FRAME_MAX_OVERHEAD + payload.len()`, write the postcard header fields in place, then encrypt the payload in place inside that single buffer, so the encoded datagram needs no second copy. Alternatively expose a `seal_into(&mut Vec<u8>)` / `encode_into(&mut Vec<u8>)` pair so the datapath can reuse one scratch buffer per connection. 1. crates/warren-multihop/src/lib.rs:275 in ClientSession::seal: `let mut buf = payload.to_vec();` allocates a fresh buffer sized exactly to the payload (no headroom) and copies the whole packet, then encrypts in place into it. Copy/alloc #1.
2. crates/warren-wire/src/multihop.rs:95 in WarrenMultihopFrame::encode: `let bytes = postcard::to_stdvec(self)?;` allocates a second buffer and re-serializes the frame, copying the entire ciphertext field (the largest, ~MTU-sized field) again plus the small header. Copy/alloc #2.
3. The hot path is confirmed: crates/warren-transport/src/multihop.rs:523 seal_and_send runs guard.seal(...) then frame.encode() then conn.send_datagram(bytes.into()) for every uplink IP packet (reached via send_packet at line 511). It is shared by real and cover traffic.

The frozen postcard layout (warren-wire/src/multihop.rs:153-167, pinned vector) places the ciphertext last as a length-prefixed trailing byte field, and MULTIHOP_FRAME_MAX_OVERHEAD=83 is a fixed prefix-only overhead, so the recommendation (assemble one buffer of capacity OVERHEAD+payload.len(), write header, encrypt in place; or expose seal_into/encode_into reusing a per-connection scratch buffer) is technically feasible and would cut 2 allocs+2 copies down to 1 alloc (amortizable to ~0 with a reused scratch) and 1 copy.

However the claimed severity (high, 'dominant CPU/alloc cost at a few hundred Mbps') is overstated. Per ~1.3KB packet the work is two small same-sized transient allocations plus two ~1.3KB memcpys, which sit alongside the unavoidable full-payload ChaCha20-Poly1305 pass and QUIC's own datagram encryption/framing copies that dominate; a modern allocator services such transient allocations cheaply. This is a real, citable hot-path inefficiency worth fixing, but it is a medium-grade micro-optimization, not a high-severity bottleneck. Also note the realistic win is 2 copies -> 1 copy (not zero-copy: the payload must still land at the correct offset after the ciphertext length varint), which the recommendation slightly glosses over.
